Privacy Policy

Last updated: 19 November 2026

There is no hosted service, no user account and no server operated by us that receives clips, video, chat logs or access tokens. This website is static and collects nothing. Everything below describes how the software behaves as implemented.

1. Scope of this policy

This policy covers two separate things:

  • This website — the pages hosted at grtling0.github.io/beststreamersmoments-website.
  • The BestStreamersMoments Clipper application — software installed and run by its operator on their own computer.

"We" and "us" refer to the operator of this project. "You" refers to the person running the application. The application is not offered as a hosted service to third parties, and no data is transmitted to us by it.

2. This website

This site consists of static HTML and one stylesheet. It sets no cookies, loads no analytics, no tracking pixels, no advertising and no third-party fonts or scripts. There are no forms, logins or comment sections, so there is nothing for us to collect.

The site is hosted on GitHub Pages. As the hosting provider, GitHub processes technical request data (such as IP address and user agent) in order to serve the pages. That processing is governed by the GitHub Privacy Statement and is outside our control. We do not receive, store or have access to those logs.

3. Twitch streams and chat

Live chat

The application connects to Twitch's public chat (IRC) service anonymously and read-only. No Twitch account is used, no Twitch login takes place, and nothing is ever posted to any chat. It joins only the channels the operator explicitly asks it to watch.

Chat messages are used to detect moments: message rate is compared against that channel's rolling baseline, with known bot accounts and repeated spam filtered out.

Chat messages saved with a clip

When a moment is detected, the messages from the surrounding seconds are saved locally alongside the clip in a metadata file. For each message this includes the sender's public Twitch display name, the message text, the timestamp and the display colour. These messages may be rendered on screen in some clip layouts (for example as chat bubbles or a chat panel).

This is publicly posted content by third parties. It is stored on the operator's computer only, is never sent to us, and is not used for profiling, advertising or any purpose other than producing the clip. If you publish a clip that displays chat messages, you are responsible for that publication — see the Terms of Service.

Video

Live video is captured from the publicly available stream into a rolling local buffer, and clips are cut from that buffer. For past broadcasts, the application can read the publicly available archived chat of a VOD through Twitch's public web endpoint and download the corresponding segments. No Twitch credentials are used for any of this.

4. Audio transcription

Captions are produced by a speech recognition model that runs on your own computer (faster-whisper). Audio is not sent to any transcription service, cloud API or third party. The model files themselves are downloaded once from Hugging Face and cached locally; that download is a normal file download and contains none of your content.

5. TikTok authentication and uploads

Authentication

TikTok is connected using TikTok's own OAuth 2.0 flow. You authorise the application in TikTok's interface; the application never sees, asks for or stores your TikTok password.

The scopes requested by default are:

  • user.info.basic — basic account identification, added by TikTok's Login Kit.
  • video.upload — sending a video to your own TikTok drafts (Inbox Upload).

The video.publish scope, which would post directly to your profile, is not requested by default. It is only requested if Direct Post mode is both explicitly enabled in the configuration and approved for the application by TikTok.

Account information accessed

From the OAuth response the application stores your account's open_id (TikTok's opaque identifier for your account in this application) and the list of scopes you granted, together with the tokens.

If Direct Post mode is enabled, the application calls TikTok's Creator Info endpoint immediately before posting. That response may include your nickname, avatar URL, available privacy options, maximum allowed video duration and whether comments, duet or stitch are disabled. It is used only to validate that specific post at that moment; it is not written to disk and not retained.

The application does not read your TikTok videos, followers, messages, analytics or any other account data.

Uploads

Video files are uploaded directly from your computer to TikTok's upload endpoint, in chunks, over HTTPS. They are not routed through any server of ours. In the default Inbox Upload mode the clip arrives as a draft in your TikTok app, and you write the caption and publish it yourself. Nothing is made public by the application.

6. YouTube authentication and uploads

YouTube is connected using Google's OAuth 2.0 desktop flow. Your Google password is never seen or stored by the application. Two scopes are used:

  • youtube.upload — uploading a video to your own channel.
  • youtube.readonly — listing the channels your signed-in account owns, so the application can verify before every upload that it is uploading to the channel you configured, and stop if it is not.

The channel list returned by that check (channel ID, title, handle, creation date, public subscriber and video counts) is used for that verification and displayed to you; only the configured channel ID is saved, in the local configuration file. Uploads go directly from your computer to Google's API.

Use of YouTube features is also subject to the YouTube Terms of Service and the Google Privacy Policy.

7. Instagram publishing

Instagram publishing is optional and off by default. It uses the Instagram Graph API with an access token you generate for your own Professional account and place in the local configuration.

The Instagram API does not accept a file upload — it downloads the video from a public URL. To satisfy that, the application temporarily serves that one clip file through a Cloudflare quick tunnel at a randomly generated trycloudflare.com address, waits for Instagram to fetch and process it, then shuts the tunnel and the local server down. While that tunnel is open, the clip file is reachable by anyone who knows the randomly generated address. Nothing else on your computer is exposed, and the address stops working once the upload finishes.

8. Optional outbound destinations

Two further destinations exist and are disabled unless you configure them:

  • Webhook — if you set a webhook URL, the application sends clip metadata to that address of your choosing. That payload includes the clip's title, description, hashtags, score, transcript and the chat messages captured with the clip, and optionally the video file itself. You choose the recipient and are responsible for it.
  • Phone / QR and folder delivery — the clip is served from your own machine on your local network, or copied to a folder you specify (for example a synced cloud-storage folder, which is then governed by that provider's own policy).

9. Where credentials are stored

OAuth tokens and API credentials are stored only on your computer, as plain files in the application's secrets directory — for example secrets/tiktok.json and secrets/youtube_token.json. They are:

  • never transmitted anywhere except to the platform that issued them;
  • never written to the application's log files or printed to the console;
  • excluded from version control;
  • protected only by your operating system's own file permissions — they are not separately encrypted, so treat that directory like any other credential store and do not copy or share it.

TikTok access tokens are short-lived and are refreshed automatically using the refresh token; TikTok issues a new refresh token on each refresh, which replaces the stored one.

10. What is stored on the computer

All working data lives in a data directory you choose (by default C:\GTA-Clipper-Data). It contains:

LocationContents
buffer/Rolling recording of the watched streams
renders/Raw source segments of cut moments, kept so a clip can be re-rendered
clips/Finished clips, their metadata (including the captured chat messages) and edit plans
transcripts/Word-level transcripts of the clips
thumbnails/Preview images
database/SQLite database of clips, publication states, watched channels and events
cache/Downloaded VOD chat and the local speech-recognition model
logs/Application logs (without credentials)

The local dashboard is bound to the loopback address and protected by a token by default, so it is not reachable from the internet unless you deliberately change that.

12. Data retention

Retention happens automatically on your own disk and is configurable. The defaults are:

DataDefault retention
Recording buffer2 hours
Raw recordings12 hours
Raw source segments for re-rendering48 hours
Cache (VOD chat, model files)14 days
Logs30 days
Finished clips and their metadataKept until you delete them

Finished clips are deliberately never deleted automatically, including when disk space runs low. Deleting them is always your decision.

13. Deleting data and revoking access

  • Clips and chat metadata: delete the clip from the dashboard, or delete the data directory. Nothing is stored anywhere else.
  • TikTok access: delete secrets/tiktok.json and remove the application in TikTok under Profile → Settings and privacy → Security and permissions → Apps.
  • Google / YouTube access: delete secrets/youtube_token.json and remove the application at myaccount.google.com/permissions.
  • Instagram access: delete the token file and revoke the app in your Meta business settings.
  • Content already published: once you publish a clip to a platform, deleting it is done on that platform.

If you are a Twitch user whose public chat message was captured in a clip that has been published, contact us using the link below and we will remove the clip in question.
